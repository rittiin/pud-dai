# พูดได้ (Pud-dai)

ต้นแบบคัดกรองอาการไข้หวัดใหญ่ (506 15), อุจจาระร่วงเฉียบพลัน (506 02) และอาหารเป็นพิษ (506 03) สำหรับประชาชน พร้อมแดชบอร์ดเฝ้าระวังสำหรับเจ้าหน้าที่

> **เดโมเท่านั้น:** ไม่ใช่บริการของกรมควบคุมโรค และไม่ใช่การวินิจฉัยทางการแพทย์ ใช้ข้อมูลสมมติเท่านั้น ห้ามกรอกชื่อ เบอร์โทร หรือข้อมูลสุขภาพจริง

## Demo

- เว็บสาธิต: https://pud-dai.vercel.app
- GitHub: https://github.com/rittiin/pud-dai
- หน้าประเมินอาการ: `/screen`
- แดชบอร์ดข้อมูลสมมติ: `/dashboard`

เว็บเดโมที่เผยแพร่ทำงานแบบอ่านอย่างเดียว ไม่บันทึกรายงานจากผู้ใช้ ไม่อนุญาตให้แก้ไขเคส และปิด AI วิเคราะห์อาการ เสียง OpenAI ในเดโมจะเปิดเมื่อเซิร์ฟเวอร์มี `OPENAI_API_KEY`; ต้องให้ผู้ใช้ยินยอมก่อนส่งข้อความที่เลือกอ่านทุกครั้ง

ก่อนเริ่มประเมิน หน้าจอจะแยกการยินยอมประมวลผลคำตอบ การบันทึก การส่งให้ AI ภายนอก การใช้เสียง OpenAI และการใช้ไมโครโฟนออกจากกัน โดยค่าเริ่มต้นตัวเลือกเสริมไม่ถูกเลือก การใช้กับผู้ป่วยจริงต้องให้ผู้ดูแลกำหนดผู้ควบคุมข้อมูล ช่องทางติดต่อ วัตถุประสงค์ และระยะเวลาเก็บข้อมูลก่อน

## เริ่มรันในเครื่อง

```bash
npm install
cp .env.example .env.local
npm run dev
```

เปิด `http://localhost:3000` หากไม่ตั้ง API key แอปใช้ตัวดึงข้อมูลภาษาไทยแบบคำค้นและรายงานแม่แบบแบบออฟไลน์

ตั้งค่า API key เฉพาะเมื่อทดสอบในเครื่อง โดยเก็บไว้ใน `.env.local` เท่านั้น:

```env
OPENAI_API_KEY=
# OPENAI_MODEL=gpt-5-mini

# ใช้ผู้ให้บริการครั้งละหนึ่งราย; ถ้ามี Typhoon key จะเลือก Typhoon เป็นค่าเริ่มต้น
# TYPHOON_API_KEY=
# TYPHOON_MODEL=typhoon-v2.5-30b-a3b-instruct
# AI_PROVIDER=typhoon | openai | custom
# AI_BASE_URL=  # ใช้เมื่อ AI_PROVIDER=custom
# AI_API_KEY=   # ใช้เมื่อ AI_PROVIDER=custom
# AI_MODEL=     # ใช้เมื่อ AI_PROVIDER=custom
```

แต่ละคำขอส่งข้อความสุขภาพไปยังผู้ให้บริการที่เลือกเพียงรายเดียว ห้ามใช้ prefix `NEXT_PUBLIC_` และห้าม commit `.env.local` ไฟล์นี้ถูก `.gitignore` กันไว้

เสียงอ่านสร้างผ่าน `/api/speech` ฝั่งเซิร์ฟเวอร์และจะเรียก OpenAI ต่อเมื่อผู้ใช้เลือกยินยอมก่อนเริ่มและกดปุ่มเสียงเท่านั้น API key ไม่ถูกส่งไปยังเบราว์เซอร์ รุ่น `gpt-4o-mini-tts` ที่ใช้อยู่ในตัวอย่างมีกำหนดปิดวันที่ 6 มกราคม 2027; ก่อนวันดังกล่าวต้องย้ายไปใช้แนวทาง Realtime API ตามเอกสาร OpenAI

คำหรือวลีที่ระบบไม่เข้าใจจะถูกถามความหมายก่อน และจะไม่ใช้จัดประเภทโดยอัตโนมัติ การส่งคำเสนอภาษาถิ่นเป็นตัวเลือกแยกต่างหาก เก็บเฉพาะคำ ความหมาย และภาษาถิ่นโดยประมาณในสถานะรอตรวจ ไม่เพิ่มเข้าคลังคำทันที เว็บเดโมสาธารณะไม่เก็บคำเสนอ ส่วนการใช้งานจริงต้องเชื่อมฐานข้อมูลที่มีสิทธิ์เข้าถึงและกำหนดวัตถุประสงค์/ระยะเวลาเก็บโดยผู้ดูแลข้อมูล

## สร้างอะไรก่อนและหลัง

Git history ปัจจุบันรวมฟีเจอร์หลักไว้ใน commit เดียว ลำดับด้านล่างจึงเป็น **ลำดับตามการพึ่งพาของระบบ** ไม่ใช่ลำดับเวลาราย commit:

1. **ฐานความรู้และกฎคัดกรอง** — `lib/flu/knowledge.ts`, `lib/flu/questions.ts`, `lib/flu/rules.ts` กำหนดคำถาม อาการเร่งด่วน และการจัดประเภท
2. **หน้าประเมินสำหรับประชาชน** — `components/Chat.tsx`, `app/screen/page.tsx` รับคำบอกเล่าและถามข้อมูลที่ยังขาด
3. **ดึงข้อมูลและตรวจหลักฐาน** — `lib/extract.ts`, `lib/ai.ts`, `lib/sanitize.ts` ใช้คำค้นหรือ AI แล้วเก็บข้อความอ้างอิงของข้อมูล
4. **ข้อมูลและเฝ้าระวัง** — `lib/store.ts`, `lib/surveillance.ts`, `components/Dashboard.tsx` สร้าง line list, epidemic curve, แจ้งเตือนกลุ่มก้อน และร่างรายงาน
5. **เผยแพร่และคู่มือ** — หน้าเว็บเดโมใช้ข้อมูลตัวอย่างแบบอ่านอย่างเดียว; `TESTING.md` บันทึกสถานการณ์ทดสอบและข้อจำกัด

ข้อมูลตั้งต้น 18 รายเป็นข้อมูลสมมติที่สร้างจากโค้ด ไม่ใช่ข้อมูลผู้ป่วยจริง

## ทำงานต่อผ่าน Codex

1. เปิดโฟลเดอร์ repo นี้ใน Codex แล้วอธิบายงานให้ชัด เช่น “เพิ่มคำภาษาถิ่นในตัวดึงข้อมูล พร้อมแก้ README”
2. ให้ Codex ตรวจ `git status` และไฟล์ที่เกี่ยวข้องก่อนแก้ จากนั้นดู diff ใน IDE
3. เมื่อตรวจการเปลี่ยนแปลงแล้ว ขอให้ Codex commit และ push ไป `origin/main` เช่น “commit การแก้ไขนี้ แล้ว push ขึ้น GitHub”
4. หลัง push ให้ตรวจ deployment ใน Vercel; ถ้า Git integration ไม่ deploy อัตโนมัติ ให้ขอ Codex รัน `vercel deploy --prod` แล้วตรวจว่าเป็น Ready ก่อนอัปเดต URL ในหัวข้อ Demo

ถ้า Codex แจ้งว่า GitHub login หมดอายุ ให้เชื่อมบัญชี GitHub ใน Codex หรือยืนยันตัวตน GitHub CLI ใหม่ก่อน push

## โครงสร้างและทดสอบ

- `app/screen` — หน้าประเมินอาการ
- `app/dashboard` — แดชบอร์ดเฝ้าระวัง
- `app/api` — API สำหรับดึงข้อมูล บันทึกเคสในเครื่อง และร่างรายงาน
- `lib/flu` — คำถาม ความรู้ และกฎจัดประเภท
- `scripts` — สคริปต์สถานการณ์ทดสอบ
- [ผลทดสอบและข้อจำกัด](TESTING.md)

การทดสอบ API แบบ end-to-end เขียนเคสลง `data/cases.json` ในเครื่อง หลังรันต้องรีเซ็ตข้อมูลสาธิต ดูคำสั่งและข้อจำกัดใน `TESTING.md`
